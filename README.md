# HR System — система автоматизации HR-процессов

## Описание проекта

**HR System** — контейнеризированная система для автоматизации основных процессов управления персоналом. Проект построен на основе микросервисного подхода и использует Docker Compose для запуска и взаимодействия компонентов инфраструктуры.

Система включает веб-шлюз, два экземпляра API, базу данных, систему обмена сообщениями, фоновый обработчик задач и инструменты мониторинга.

## Основные возможности

- Управление сотрудниками.
- Работа с вакансиями.
- Обработка заявок на отпуск.
- Получение сводной информации через панель HR-системы.
- Обработка фоновых событий.
- Балансировка запросов между двумя экземплярами API.
- Сбор и визуализация метрик инфраструктуры.
- Контроль состояния контейнеров и сервисов.

## Архитектура проекта

В проекте используются следующие контейнеры:

| Контейнер | Назначение |
|---|---|
| `gateway` | Nginx — входная точка системы и балансировщик нагрузки |
| `api-1` | Первый экземпляр HR API |
| `api-2` | Второй экземпляр HR API |
| `postgres` | PostgreSQL — хранение данных |
| `redis` | Redis — обмен событиями и временное хранение данных |
| `worker` | Фоновая обработка событий |
| `prometheus` | Сбор и хранение метрик |
| `grafana` | Визуализация метрик и создание панелей мониторинга |
| `cadvisor` | Сбор метрик контейнеров |
| `nginx-exporter` | Передача метрик Nginx в Prometheus |
| `postgres-exporter` | Сбор метрик PostgreSQL |
| `redis-exporter` | Сбор метрик Redis |

Всего инфраструктура включает **12 контейнерных сервисов**.

## Используемые технологии

- **Docker** — контейнеризация приложений.
- **Docker Compose** — управление многоконтейнерной инфраструктурой.
- **Nginx** — обратный прокси-сервер и балансировка нагрузки.
- **Python / FastAPI** — разработка серверного API.
- **PostgreSQL** — реляционная база данных.
- **Redis** — обмен событиями и временное хранение данных.
- **Prometheus** — сбор и хранение метрик.
- **Grafana** — визуализация показателей.
- **cAdvisor** — мониторинг ресурсов контейнеров.

## Схема взаимодействия

Пользователь отправляет запрос через веб-интерфейс. Запрос поступает на Nginx Gateway, который распределяет нагрузку между двумя экземплярами HR API.

API взаимодействует с PostgreSQL для работы с данными и Redis для обмена событиями. Фоновый обработчик Worker выполняет обработку событий.

Prometheus получает метрики от приложений и экспортёров. Grafana использует собранные данные для отображения состояния инфраструктуры.

## Запуск проекта

### Требования

Перед запуском необходимо установить:

- Docker Desktop;
- Docker Compose;
- Git.

### Клонирование репозитория

```bash
git clone <URL_РЕПОЗИТОРИЯ>
```

Перейдите в каталог проекта:

```bash
cd System_HR
```

### Запуск контейнеров

Соберите образы и запустите сервисы:

```bash
docker compose up -d --build
```

### Проверка состояния контейнеров

```bash
docker compose ps
```

### Просмотр логов

```bash
docker compose logs -f
```

### Остановка проекта

```bash
docker compose down
```

Для остановки с удалением контейнеров и сохранением данных в именованных томах используется команда:

```bash
docker compose down
```

## Доступ к сервисам

После запуска проекта основные сервисы доступны по следующим адресам:

| Сервис | Адрес |
|---|---|
| HR System | http://localhost:8080 |
| Prometheus | http://localhost:9090 |
| Grafana | http://localhost:3000 |
| Статистика Nginx | http://localhost:8080/nginx_status |

Доступность отдельных страниц и API-маршрутов зависит от конфигурации приложения.

## Сетевая инфраструктура

Для взаимодействия контейнеров используется общая виртуальная сеть Docker — `hr-network`.

Сервисы обращаются друг к другу по именам контейнерных сервисов и внутренним портам. Это позволяет организовать взаимодействие компонентов без необходимости публиковать каждый внутренний порт на хостовую машину.

## Балансировка нагрузки

Для распределения запросов между экземплярами API используется Nginx.

В конфигурации предусмотрены два сервера:

- `api-1:8000`;
- `api-2:8000`.

Для распределения запросов используется алгоритм `least_conn`, который направляет новый запрос на сервер с наименьшим количеством активных соединений.

## Мониторинг

Для наблюдения за состоянием инфраструктуры используется стек мониторинга Prometheus и Grafana.

Prometheus собирает метрики с приложений и экспортёров. cAdvisor предоставляет информацию об использовании ресурсов контейнеров, а специализированные экспортёры передают показатели Nginx, PostgreSQL и Redis.

Grafana позволяет отображать собранные показатели в виде графиков и панелей мониторинга.

## Хранение данных

Для сохранения данных между перезапусками контейнеров используются именованные тома Docker:

- `postgres_data`;
- `redis_data`;
- `prometheus_data`;
- `grafana_data`.

Это позволяет сохранять данные сервисов независимо от жизненного цикла отдельных контейнеров.

## Структура проекта

Основные компоненты проекта организованы по отдельным каталогам и конфигурационным файлам. В частности, используются:

- `docker-compose.yml` — описание сервисов, сетей и томов;
- конфигурация Nginx — настройка шлюза и балансировки;
- конфигурация Prometheus — настройка сбора метрик;
- исходный код HR API;
- исходный код фонового обработчика Worker;
- конфигурация Grafana и экспортёров.

## Назначение проекта

Проект демонстрирует построение контейнеризированной инфраструктуры HR-системы, организацию взаимодействия сервисов, использование двух экземпляров серверного API, балансировку нагрузки и мониторинг состояния компонентов.
